# 园区用电运营业务数据

来源事件有来源编号、事件编号、修订、外部实体、发生时间和观察时间；同一来源同一事件的更高修订替代先前修订。主体映射只在来源与外部标识的组合内有效，无法映射的事件在现有摘要中列为未归属。通用金额是原始事件上的可选数值，不代表利润、节约额或结算结果。

报告发布接口保留报告正文和摘要哈希，相同编号不接受不同内容。业务口径、结论的适用范围和后续变化的影响需要与原始观察区分。

## 需求响应分析

### 报名与生产日历（修订留痕）

响应报名与生产停线都是追加式修订，而不是就地覆盖：

- 报名（`enroll`）记录事件编号、园区、承诺削峰量、事件时段起止和观察时间；同一事件同一园区再次登记即产生更高修订。撤销报名（`cancel_enrollment`）写入墓碑修订，历史时间点仍能读到当时有效的承诺。
- 停线日历（`record_shutdown` / `cancel_shutdown`）按园区与日期维护修订序列；停线更正或撤销同样留痕。
- 所有读取接口接受 `as_of`，只返回该时间点之前已观察到的最新修订，保证已确认结论可按当时数据重现。

### 可比基线

计量事件（`meter`）按园区解析后，以事件时段覆盖的计量区间为单位：

- 回看事件日前 14 个自然日，逐日判断是否可比：停线日剔除（自然降耗不可比），计量区间不完整的日期按数据缺口剔除。
- 可比日不少于 3 天才视为基线充分；对事件时段内每个区间取可比日均值，区间均值之和为事件时段基线总量。
- 被剔除的日期及原因（生产停线 / 计量数据缺口）随评估结果返回，基线不足时整体暂不能结算。

### 实际响应与归因

- 实际用量取事件时段内已到计量区间之和；任一区间缺失即标记数据缺口，缺口补齐前不出实际总量。
- 毛降幅 = 基线总量 − 实际总量，仅描述观察到的用电下降。
- 只有事件日未停线且无计量缺口（同时基线充分）时，降幅才可归因于已确认的响应，记为可归因降幅；事件日停线、基线不足、时段缺口任一存在，结论为“暂不能结算”，毛降幅仍展示但不得用于结算。
- 可结算时以可归因降幅与承诺量比较，给出履约比例与是否兑现承诺。

### 履约报告与补传、更正的影响

- `publish_response_report` 把发布时点（`as_of`）的完整评估固化进报告正文；计量补传或停线更正只产生新修订，不改变已发布报告。
- `replay_response_report` 按报告固化的时间点与输入重新评估，结果与正文逐字段一致时报告才被视为可重现。
- `affected_response_reports` 用当前数据重算每份履约报告，列出结论或输入发生变化的报告及具体字段（计量点修订、停线日、基线、实际用量、可归因降幅、履约结论等），供运营决定是否重新出具报告；未变化的报告不列出。
